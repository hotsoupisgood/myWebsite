Writing Style Guide #

Apply these when drafting or editing prose content in this repo (blog posts, project write-ups). Don't apply the punctuation/tone rules to code, front matter, URLs, or file paths.

Punctuation #

  • No em dashes.
  • No colons used stylistically in prose (e.g. to introduce a list or clause). Split into separate sentences instead. YAML front matter and URLs are exempt.
  • No hyphens in compound modifiers — use a space instead, even if it reads as grammatically nonstandard. "time series" not "time-series", "one off" not "one-off", "region specific" not "region-specific", "week to week" not "week-to-week". Never touch hyphens inside file paths, slugs, or URLs.

Spelling #

  • Blog and project posts: American spelling (penalized, standardize, artifact).
  • Formal academic writing (thesis, reports): British spelling, kept internally consistent (standardised, modelling, colour, centre, utilise). Don't mix the two within one document.

Tone and claims #

  • Don't overstate what's shown. A visual observation (e.g. a map or chart) isn't itself a statistical claim — state the visual pattern and the statistical backing as separate, clearly connected points rather than asserting a strong claim up front.
  • Be precise about what a model was told versus what it inferred. Don't describe a model as "discovering" or "independently recovering" something if its structure or timing was specified in advance — only claim independence for what was actually estimated from data.
  • Reuse the correct formal term from the underlying analysis even in casual writing (e.g. "sensitivity analysis," not "we double-checked").
  • Cut throat-clearing opening sentences that state the obvious framing (e.g. "This is my MSc thesis..."). Get to the substance.
  • Prefer plain word choices over fancier ones (e.g. "uses" over "reaches for").
  • Drop informal hedge phrases like "not just eyeballed."

Links and citations #

  • Verify a link actually resolves and supports the claim before adding it. Fetch and check; never guess or fabricate a URL.
  • Weave links directly into the sentence. Don't bolt on a "like [this article]" clause.
  • Only add a specific stat or claim if it's backed by real, checkable data — cite an existing figure from the source material rather than inventing one.

Terminology consistency #

  • When a post describes another document (e.g. a thesis), match that document's defined terms exactly, so the two don't drift apart. Example: "regional level" not "baseline level"; "annual cycle" not "winter cycle."
